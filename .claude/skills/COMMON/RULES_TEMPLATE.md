# 🔒 Wiki 重新整理 - 規則範本（所有國家通用）

## 目錄結構規則
```
wiki/{國家}/{一級區域}/{二級區域}/*.md
```
- **三層結構**：必須有一級區域 → 二級區域兩層
- **不准有"其他"資料夾**：所有檔案必須分類到具體的二級區域

---

## Case 定義（所有國家統一）

### Case 1: 驗證正確位置的檔案
**掃描位置**：`wiki/{國家}/{一級區域}/{二級區域}/*.md`
**功能**：
- 檢查座標是否真的在指定的二級區域邊界內
- 報告位置正確或錯誤
**輸出**：位置正確數 / 位置錯誤數 / 無法定位數

### Case 2: 清空"其他"目錄
**掃描位置**：`wiki/{國家}/{一級區域}/其他/*.md`
**功能**：
- 根據座標找到正確的二級區域
- 移動檔案到正確位置
- **重要規則**：目標檔案已存在 → 刪除源檔案（只保留一份，不加序號）
- 清理所有空的"其他"資料夾
**輸出**：已移動數 / 移動失敗數 / 無法定位數

### Case 3: 處理缺少二級區域層級的檔案
**掃描位置**：`wiki/{國家}/{一級區域}/*.md`（直接在一級區域下）
**功能**：
- 根據座標找到正確的二級區域
- 移動檔案到正確位置
**輸出**：已移動數 / 移動失敗數 / 無法定位數

## 技術細節（統一標準）

### 座標系統
- WGS84 (GPS 座標)
- 格式：`coordinates: [lng, lat]`

### 邊界資料
- 格式：GeoJSON MultiPolygon
- 座標驗證方法：射線投射演算法 (Ray Casting)，加入邊界容差
  - 容差值：`1e-3`（約 100m 級別）
  - 原因：某些座標可能正好在行政邊界上或非常接近，純粹的演算法判定會失敗
  - 實現：計算點到邊界線段的距離，若小於容差視為「在多邊形內」

- **重要**：某些 GeoJSON 檔案可能包含重複的區域（例如同一鄉鎮市區分成多個 feature）
  - 原因：行政邊界可能包含多個不連續的區域（如離島、飛地等）
  - 解決方案：在 `load_geojson_regions()` 中自動合併重複區域的所有 polygon
  - 實現：先檢查 key 是否存在，不存在則建立新條目，存在則 extend coordinates

### 進度報告
- **頻率**：每 10 秒報告一次
- **格式**：
  ```
  ⏱️ [時間] 進度: 已處理/總數 (百分比) | 統計數據 | 預計剩餘時間
  ```

### 檔案移動規則
1. 建立目標目錄 `wiki/{國家}/{一級區域}/{二級區域}/`
2. 檢查目標檔案是否存在
3. 如果存在 → **刪除源檔案**（保留目標）
4. 如果不存在 → 移動源檔案到目標位置

## 已知限制

### 「無法定位」的座標
某些座標會被標記為「無法定位」，常見原因：
1. **座標在邊界外**：
   - GeoJSON 檔案可能不完整，如：台灣高山、離島可能不在 GeoJSON 中
   - 座標可能在海上或超出國家邊界
2. **座標資料錯誤**：
   - 座標本身有誤差或輸入錯誤
3. **GeoJSON 縫隙**：
   - 相鄰區域邊界之間的細小縫隙（浮點精度問題）

**解決方案**：
- 對於高山和離島區域，考慮手動驗證和分類
- 對於明顯的錯誤座標，應在源資料進行修正
- 不建議強制移動無法定位的檔案（會造成誤分類）
